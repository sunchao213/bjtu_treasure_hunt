# 游戏流程修复与浏览器验证（2026-11-05）

## 修复范围

- 大厅明确区分单人探索与组队探索，移除旧 `BJTU-xxxx` 演示通道和局内房间表单。正式房间统一使用已登录账号的同源 `/ws` 服务及服务器生成的 6 位数字房间号。
- 大厅隐藏地图时，Phaser 使用非零尺寸初始化渲染器；资源与场景完成初始化后才允许开局。资源失败、动画帧缺失或场景初始化异常时提供可见的重新加载入口，避免在半初始化地图中开始探索。
- 隐藏地图或切换视图期间产生的无效鼠标坐标不再改变朝向。联机输入也校验有限坐标，避免 `Invalid client network message` 异常中止整个游戏循环。
- 修复升级后的图片缓存混用：11 月 3 日的怪物图片帧高为 128，当前为 176，之前仍使用相同地址，旧浏览器缓存会导致 `SpriteSheet frame dimensions will result in zero frames` 和 `Missing animation frames: duck-idle`。所有场景图片地址现在携带由图片内容计算的版本标识；图片变化时，代码和缓存标识一起更新。失败重载按钮也收进状态行，避免占据整块装备区域。
- 准备或保存期间阻止重复开局；房间请求有超时恢复，已结束成员不会因新的房间快照重复开局。
- 房间开始／准备按钮固定在页面底部；成员和装备区可滚动。局内地图与侧栏分别布局，结果以独立结算层显示。
- 默认携带训练棍，显示当前账号和云存档信息。序章观看／跳过后按账号记住本机偏好，规则由玩家主动打开。
- 修复昵称遮脸和地图黄色方块：昵称锚定在角色完整动画帧上方，在夜幕之上保持固定屏幕字号，并跟随角色移动与移除；删除地图自带路灯之外的重复矩形，继续使用原有照明和充电范围。

## 运行验证

```powershell
npm.cmd run check
npm.cmd run test:server
npm.cmd run test:browser
```

浏览器回归使用本地生产构建、真实 Chrome／Edge、ASP.NET 服务及独立 SQLite 数据库。可通过 `BROWSER_PATH` 指定 Chromium 浏览器。证据、截图和服务日志位于被 Git 忽略的 `artifacts/game-flow-时间戳/`；不会连接公网服务器或写入真实账号。

自动检查包括：

1. 注册登录、加载就绪、风险确认、单人开局、计时、实际按键移动和小地图位置变化。
2. 规则暂停／继续、放弃后的云端结算、返回大厅、再次开局以及 900×500 桌面窗口。
3. 两个独立账号创建／加入房间、准备门槛、同时开局，以及队友实际收到服务器位置变化。
4. 一人先结束时等待其余成员、全员结束后准备下一局、连续两局、退出房间并切回单人。
5. 390×844 触屏设备的横屏布局与单人开局。
6. 故意阻止角色图片加载，确认显示恢复入口、开始按钮禁用且没有开始对局。
7. 浏览器全程没有未捕获异常。
8. 在独立的安装文件副本中提供 128 像素旧图片，并用真实 HTTP 缓存保留这些图片；随后服务器文件升级到 176 像素，确认无版本地址仍读到旧图片，再验证新版无需清空浏览器数据即可开局、计时和显示小地图。此用例在修改前复现了截图中的初始化失败。

最终生产构建的浏览器回归记录位于 `artifacts/game-flow-1793859038486/`。另在独立本地账号中完成了真实按住 E 搜索四个容器、成功带出 4 件物品（价值 135）、返回大厅并刷新，刷新后仓库仍为 4 件，记录位于 `artifacts/flow-verification/browser-1793859090565/`。该补充验证仅在测试浏览器内固定角色位置并关闭战斗干扰，搜索输入、背包、剧情、撤离和 HTTP 云存档均使用真实流程。

缓存故障复现记录为 `artifacts/game-flow-1793860718812/`：保留旧图后，修复前的构建显示与用户相同的初始化失败。加入图片内容版本后，同一缓存场景与其余浏览器流程全部通过，记录为 `artifacts/game-flow-1793861853383/`，`08-cache-upgrade.png` 为保留旧缓存时的正常单人游戏截图。

显示修复另通过真实浏览器检查，记录为 `artifacts/flow-verification/public-init-1793865221120/`：昵称与角色帧间隔 6 个世界像素，1.7 与 2.3 倍镜头下文字高度均为 19 个屏幕像素，黄色路灯矩形数量为 0；长昵称、队友昵称和队友退出后的标签移除均正常。该检查固定角色位置并关闭战斗干扰，只在本地模拟账号与存档。

这些浏览器检查不等于随机地图全路线试玩，也不覆盖完整合作战斗；房间目前仍只共享位置和本轮地图布局。搜索、计分、撤离和云存档规则另有现有单元与集成测试。不同显卡、真实手机触控手感与公开服务器上的最终验收仍需实际试玩。

## 更新服务器

运行 `scripts/package-ubuntu.ps1` 生成新的 ZIP 与 SHA256，按[Ubuntu 部署说明](ubuntu-deployment.md)上传、校验并执行安装脚本。健康检查只代表服务可响应；安装后还应核对 `release.json`，并在公网浏览器实际验证单人开局、角色移动和组队流程。

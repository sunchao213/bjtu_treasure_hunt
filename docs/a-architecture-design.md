# A 第十周概要与详细设计

本稿对应项目计划第十周（2026-11-14 至 20 日）A（孙志超）负责的档案、聊天与联机门槛，并给第十一周跨模块联调提供稳定接口。好友关系由许诺负责；本实现只提供聊天必需的申请/响应/删除/屏蔽授权边界，好友列表和后续排行仍由该模块扩展。大厅、背包、图鉴、商城和邮件页面由对应负责人维护。

第十一周时装购买、预览、换装和联机档案联调的实现记录见 [`a-implementation.md`](./a-implementation.md)。客户端按时装 ID 加载游戏内置资源，账号只保存时装 ID 与资产状态，不保存玩家自带资源 URL。

## 模块边界

| 模块       | 权威数据                                                   | 本周接口                              | 负责人协作                                                         |
| ---------- | ---------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------ |
| 账号与会话 | 登录 Cookie、账号 UID、昵称                                | 现有 `/api/auth/*` 与 `/ws` 会话      | 全模块以会话 UID 识别本人，不从请求体取身份                        |
| 对局档案   | 云存档 `lastResult` 的真实结算快照、服务端收录时间         | `GET /api/profile/self`               | 存档提交时按 UID 与 `raidId` 唯一记录；不为历史空档补造结果        |
| 好友关系   | UID 对、申请人、状态、屏蔽方向                             | `/api/friends*`                       | 许诺后续扩展好友完整交互；接受好友是公开档案与私聊的必要条件       |
| 私聊       | 消息序号、消息 ID、发送/接收 UID、纯文本、创建时间、读游标 | `/api/messages`、`/api/messages/read` | 好友权限和屏蔽状态由服务端检查；客户端仅按序号补取                 |
| 房间       | 房主、成员会话 UID、准备状态、房间规则、对局状态           | 已有 WebSocket 房间协议               | 房间创建、加入、准备及开局时检查已保存的三章通关；开局再次检查全员 |

## 档案与隐私

云存档每次成功提交时，如果快照含合法 `lastResult`，服务端将其原样放入 `raid_history`，主键为 `(user_id, raid_id)`，重试不会重复记录。新账号与没有 `lastResult` 的账号返回空历史。当前存档没有历史对局时间或模式字段，`recordedAt` 表示服务端首次收录时间，不代表实际开局时间；结果详情只展示快照中确实存在的字段。

本人接口返回完整历史、当前存档及公开开关。好友公开接口只接受已接受且未屏蔽的好友，且需本人开启展示；响应白名单为 UID、昵称、最多 6 个图鉴展示 ID 和最近 20 条对局摘要，不返回余额、仓库实例、账号名或私聊。关闭开关立即影响后续读取。未知、非好友和关闭公开统一返回不可用，避免暴露账号隐私状态。

## 好友与消息

关系按两个 UID 排序后唯一存储。申请同 UID 对幂等；响应必须由非申请人执行。接受后允许一对一私聊；删除结束关系但保留消息记录。屏蔽按发起方保存，同时删除当前好友关系，并阻止新申请与消息。恢复消息只接受本人和好友 UID，不接受客户端指定 sender。

发送请求为 `POST /api/messages`，载荷 `{ messageId, toUid, text }`。文本按 Unicode 字符计数，长度 1–200 且不含控制字符；每个发送者任意 10 秒最多 5 条。`(sender_id, message_id)` 唯一：相同 ID 与相同内容返回既有消息，不同内容返回 `IDEMPOTENCY_CONFLICT`。消息保存成功后才返回服务器序号。离线补取使用 `GET /api/messages?with={uid}&after={sequence}`，最多 100 条；`POST /api/messages/read` 只推进本人接收游标。未读数从消息与读游标计算，不信任客户端计数。前端将文本写入 `textContent`，不解析 HTML。

## 联机门槛

创建、加入、准备及开局请求使用 WebSocket 登录会话 UID查询服务端云存档，必须保存有 `siyuan-code`、`siyuan-key`、`soothe-monster` 三个章节完成 ID。开局在房间锁内再次检查每位成员；若任一成员不满足，返回 `ONLINE_LOCKED` 与成员昵称，不切换房间状态、不生成本轮宝箱、不扣除带入物。房间至少两人才能开始合作探索。资格检查故障按拒绝处理，不能降级放行。

## 错误与恢复

| 场景                     | 状态/错误码                     | 客户端处理                 |
| ------------------------ | ------------------------------- | -------------------------- |
| 未登录                   | HTTP 401                        | 返回登录入口               |
| 非好友、屏蔽或非公开档案 | HTTP 404/403                    | 不展示他人私有资料         |
| 消息 ID 复用但载荷不同   | HTTP 409 `IDEMPOTENCY_CONFLICT` | 保留原消息，不显示为成功   |
| 发送超频                 | HTTP 429 `MESSAGE_RATE_LIMIT`   | 提示稍后重试               |
| 开局时任一成员失去资格   | WebSocket `ONLINE_LOCKED`       | 留在候场，显示未达标成员   |
| 服务端数据库异常         | HTTP 503                        | 保留页面状态，允许显式重试 |

## 第十周交付与联调

- 档案：真实 `lastResult` 归档、本人列表/详情、好友公开开关与白名单。
- 聊天：好友授权、纯文本限长、服务端限频、持久化幂等、序号补取、未读/已读游标。
- 联机：开局全员门槛复核及至少两人限制，保留现有房间准备、容量和房主权限流程。
- 验证：`npm run test:server` 覆盖真实历史写入、好友授权、隐私边界、消息幂等与未读游标，以及成员资格撤销后的开局拒绝。

下一轮需与许诺的正式好友页面对接，并与项会惠对接藏品展示 ID；模式、真实对局发生时间和更完整的个人结算详情需要由统一结算数据合同提供后再展示。当前联机世界仍未把战斗、个人撤离与权威结算接入房间服务，这些不应以本周门槛实现代替。

# 交大南门样板：资源调查与 Blender 接入

2026-11-20。保留当前固定正交镜头、55°俯角、人物精灵动画和键鼠操作，给独立三维试验页接入真实地标外观的低模样板。

## 网站实际提供什么

检查了 <https://map.bjtu.edu.cn/> 的页面、地图加载脚本、地图配置及南门 VR 全景。**这两条已检查的展示路径提供图片，不是可直接导入 Blender 的建筑网格。** 不能据此断言学校或供应商没有三维源文件，但这些网页路径没有分发可用的 GLB、glTF、OBJ、FBX 或 3D Tiles。

| 路径         | 实际格式与组织                                                             | 复用方式                     |
| ------------ | -------------------------------------------------------------------------- | ---------------------------- |
| 校园立体地图 | 256×256 JPG，`mapdata/zoom{level}/{column}_{row}.jpg?v=20260624`，四级缩放 | 建筑轮廓、配色和布局参考     |
| 地点数据     | XML，`xml/gadgets/{level}/{column}_{row}.xml`                              | 名称、图片地图坐标和全景入口 |
| 南门 VR      | Pano2VR 7.1.9 六面 JPG；面宽 2957／1478／739／369，瓦片 510、重叠 1 像素   | 现场外观参考，无深度网格     |
| 地图下载     | `html2canvas` 导出 PNG                                                     | 网页截图，不是模型导出       |

网站“南门”标记位于图片地图坐标 `(14763,13052)`，对应全景名称“东校区南门”，入口为 <https://map.bjtu.edu.cn/qj/bjdzx93/index.html>。本样板明确依据这一地点，不当作另一座校门的精确模型。

用户已确认资源复用授权。两张参考图及详细来源记录在 `assets-source/campus-3d/reference/`。引擎脚本和定位过程资料仅保留在忽略提交的 `artifacts/campus-3d/`。网页运行时不请求学校网站。

## 已制作的样板

由于没有可复用网格，采用参考重建：在 Blender 5.2.3 LTS 中制作红褐色石材拱门、金色校名、门卫室、铺地和简化教学楼，按区域和材质合并后导出 GLB，再把实际 GLB 重新导入 Blender 核对。

校门外观有具体参考；教学楼提取周边楼体特征，位置按原试验地图适配，搜索和撤离路线保持原样。因此这是游戏样板，不是完整南门区块的测绘还原，也不是官网原模型。门顶圆饰不宣称为精确校徽。

| 文件                                                  | 用途                                               |
| ----------------------------------------------------- | -------------------------------------------------- |
| `assets-source/campus-3d/south-gate.blend`            | 可编辑 Blender 源文件，保留建筑部件与打包纹理      |
| `scripts/build_south_gate_sample.py`                  | 建模、整理、导出及重新导入后的预览生成脚本         |
| `assets-source/campus-3d/south-gate-layout.json`      | Blender 与游戏共用的比例、校门、教学楼、门卫室占地 |
| `assets-source/campus-3d/*.png`                       | 三张自制 256×256 纹理：石材、墙面、入口砖          |
| `public/assets/models/bjtu-south-gate/south-gate.glb` | 网页加载模型，几何、材质和 PNG 全部内嵌            |
| 同目录 `asset-report.json`                            | 资源规模、优化和校验摘要                           |

导出前合并相同材质的区域网格，移除无贴图材质的多余 UV，再通过 glTF Transform 4.2.1 执行 `dedup`、`prune`。最终 **626,036 字节（约 611 KiB）、17 个网格、9,280 个三角形、10 个材质、3 张 PNG**。Khronos glTF Validator 为 **0 错误、0 警告、0 提示**。

重新生成命令（项目根目录）：

```powershell
& 'E:/Blender/blender.exe' --background --factory-startup --python scripts/build_south_gate_sample.py
```

脚本覆盖同名生成文件，直接输出有效的 GLB（约 617 KiB）；交付文件额外执行上述清理。两者都无需在线解码器。修改过 Blender 源文件后，应另存再重跑脚本。脚本运行不需要联网。

Blender 使用 Z-up、负 Y 对应地图南，导出转换到 glTF Y-up；32 地图单位等于 1 世界单位。模型在浏览器中不再凭目测缩放。

## 接入与验证

- 采用项目当前版本的 `GLTFLoader` 从本地 `BASE_URL` 加载，不升级 Three.js。
- 替换初版占位门梁和教学楼，加入门卫室；人物、宝箱、碰撞移动与搜索撤离逻辑继续复用。
- 门柱和门卫室占地来自共用布局；门洞中央可通过，撤离区保持原位置。
- 高拱门会遮住固定镜头下的人物，使用真实网格射线判断遮挡，并平滑淡出门体；镜头角度和人物操作不变。
- 加载完成和 WebGL 恢复后重新更新静态投影，卸载时回收几何、材质、纹理和阴影。
- 新增三项测试读取实际 GLB 三角形，验证门洞没有封死、门柱及门卫室与碰撞对齐、纹理内嵌和文件预算。原九项试验会话测试继续通过。
- 使用独立无头 Edge 会话，以真实键鼠行走搜索四只宝箱取得 100 价值，模拟 WebGL 中断与恢复后主动继续，返回南门完成五秒撤离并成功保存，再次开局。页面错误、资源 HTTP 错误为零。
- 对最终优化后的 GLB，在正式构建挂载于 `/demo/` 的子目录中重复上述完整流程通过；没有外部网络请求，贴图和模型均由本地构建目录提供。
- 1600×1000 的一次稳定采样约 60 FPS，平均 16.7 ms、P95 16.8 ms，77 次绘制、73 个几何体、8 张纹理；启动期明显更慢，不代表全设备性能或显存字节数。

本地截图与记录：`artifacts/campus-3d/south-gate-game.jpg`、`south-gate-settlement.jpg`、`south-gate-browser-report.json`、`south-gate-validation.json`。Blender 的重导入预览为 `south-gate-blender-preview.png`。

项目检查：ESLint、类型检查、58 个测试文件／418 项测试、3 项数据库测试及正式构建均通过。总命令 `npm.cmd run check` 在全库格式阶段被 `src/main.ts`、`docs/delivery/d-changelog.md` 两个非本次编辑文件的格式问题阻断；本次编辑文件单独格式检查通过，未重排其他正在修改的代码。构建另有原页面 `/assets/fonts/zpix.ttf` 缺失的提示，与南门模型无关；本次三维浏览器流程未请求该字体。

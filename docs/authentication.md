# 账号登录与云存档

游戏必须先通过服务端登录校验。未登录或账号服务不可用时只显示账号页面；地图、音频、存档和联机连接均在登录验证后初始化。注册成功直接登录，刷新可恢复有效会话。

## 本地运行

需要 Node 24、npm 11 和 .NET 8 SDK（或兼容更新版本）。在项目根目录打开两个终端：

```powershell
# 终端一：账号、数据库和联机服务
dotnet run --project server/OnlineHost.csproj --urls http://127.0.0.1:5080
```

```powershell
# 终端二：前端，首次运行先安装依赖
npm.cmd ci
npm.cmd run dev
```

打开 `http://127.0.0.1:5173`，注册账号后进入游戏。用户名为 3–24 位字母、数字或下划线，不区分大小写；昵称最多 18 字；密码为 8–128 位。服务端首次启动自动创建 `server/data/game.db`，不需要另装数据库服务。

Vite 将同源 `/api` 和 `/ws` 代理到 5080，保留原 Host，联机自动沿用登录账号。`npm.cmd run preview` 同样提供代理。服务未启动时可在账号页重新检查登录状态。

## 会话与存档

- 账号保存在 SQLite，密码使用独立随机盐和 PBKDF2-SHA256（210,000 轮）哈希，不保存明文。数据库位置、旧账号迁移与备份见[数据库说明](database.md)。
- 登录使用 HttpOnly、SameSite=Strict Cookie，HTTPS 下设置 Secure；前端不保存密码或登录令牌。会话有效期为 12 小时，服务重启后需重新登录，账号和已确认进度保留。
- 注册、登录按来源 IP 限制每分钟 20 次；写接口检查来源与请求头，认证及存档响应禁止缓存。
- 退出或会话到期会撤销会话、中断 WebSocket 并释放云存档占用。页面定期及返回前台时检查会话，多标签页同步退出和账号切换。
- 仓库、图鉴、章节解锁、最近结算和未结束探索按账号保存在数据库；换设备连接同一服务、登录同一账号即可读取。浏览器仅缓存备份，远端已有存档时始终优先读取远端。
- 云端还没有存档时，自动上传当前账号的旧浏览器存档。添加登录前的共享存档仍需在“当前账号”中明确确认迁移，迁移会覆盖当前账号云进度，原共享存档保留。
- 同账号同一时间只允许一个游戏窗口使用存档：浏览器 Web Lock 防止本机冲突，服务端 90 秒租约防止跨设备冲突，每 20 秒续约。正常离开会释放，异常断线需等待租约到期。
- 开局和结算等待数据库确认后才更新当前进度；失败时保留原确认状态，可重试。断网无法可靠保存，租约失效后停止当前游戏并重新读取进度。局中刷新、关闭或异常退出，下一次进入按中断失败处理，带入物会损失。
- 游戏内可导出 JSON 进度备份；清空存档会更新当前账号的云进度，需要明确确认。数据库备份还包含账号，与游戏内导出不同。

## 部署与检查

运行 `npm.cmd run build` 后，同一个 ASP.NET 服务可提供 `dist/`、`/api` 和 `/ws`，访问 `http://127.0.0.1:5080`。正式环境使用 HTTPS/WSS，数据库目录必须持久保存；一个数据库由一个宿主管理。反向代理保留原 Host，正确转发 `X-Forwarded-Proto` 并支持 WebSocket。服务只信任 ASP.NET 默认的回环代理来源，其他代理拓扑需配置可信代理。纯静态托管需增加同源后端或代理。

```powershell
npm.cmd run check
npm.cmd run test:server
```

前者检查格式、类型、前端与数据库测试和构建；后者构建 .NET 并在独立临时目录验证旧账号迁移、密码哈希、登录保护、WebSocket 撤销、账号隔离、云存档读写、租约、版本冲突、重试及重启持久化，不写入真实账号目录。

当前战斗与掉落仍在客户端模拟，云存档负责持久化和写入冲突保护；完整权威战斗结算尚未实现。

# 电脑与手机网页并行测试

电脑端先验证完整对局与存档，手机端同步验证触屏输入和布局。两条测试线使用同一个网页游戏；每个测试者各自进行单人对局，存档保存在自己的浏览器。本文是验收清单，不代表其中所有场景已通过人工测试。

电脑端使用键盘和鼠标，不显示手机摇杆或技能按钮；缩小电脑窗口仍保留电脑操作方式。手机等以触屏为主要输入、没有悬停指针的设备自动显示左侧摇杆和右侧操作按钮，摇杆方向同时决定朝向，右侧可搜索/交互、攻击、切换手电、换电池和放置照明棒。

## 本地检查与发布

在项目根目录使用 Node 24、npm 11：

```powershell
npm.cmd ci
npm.cmd run check
```

检查通过后，`dist/` 是发布文件夹。将整个 `dist/` 上传到支持 HTTPS 的静态托管网站，再把固定网址发给测试者。每次更新重新构建，并上传到同一个站点，保留网址和浏览器存档来源。公开托管完成后，本机可以关闭。

本项目没有测试结果汇总后台。发放链接时同时提供反馈表，记录版本日期、设备型号、系统、浏览器、复现步骤和截图。不要用开发服务器上的模拟伤害按钮评价正式游戏体验。

### 网络与浏览器

- `localhost` 和 `127.0.0.1` 仅供当前电脑访问，不能当作公共测试链接。
- 手机访问本机服务需要可互通的局域网、本机服务持续运行及防火墙放行。当前开发命令默认绑定 `127.0.0.1`，其他设备不能直接连接。
- 存档单写者保护依赖 Web Locks，通常需要 HTTPS 或当前设备自己的 localhost。手机访问电脑的普通 HTTP 局域网地址不能作为存档兼容验收环境。
- 优先使用电脑 Chrome/Edge、Android Chrome 和 iPhone Safari。微信内置浏览器单独记录兼容性，不能默认其已支持所有能力。
- 同一来源的多个标签页共享存档；不同设备、浏览器、端口、域名和协议的存档不会自动同步。不要在重要对局中切换浏览器或清理站点数据。

## 电脑端验收

| 场景         | 通过标准                                                                             |
| ------------ | ------------------------------------------------------------------------------------ |
| 准备与开局   | 未确认损失提示不能开局；确认后只开始一局，生命、计时和背包正确显示                   |
| 移动与碰撞   | WASD、方向键正常；斜向速度合理；建筑、湖面和地图边界不会穿过                         |
| 电脑操作布局 | 大窗口与窄窗口均隐藏手机摇杆和技能按钮；键位说明可见，鼠标瞄准正常                   |
| 搜索         | 靠近物资点，持续按 E 完成搜索；松开、离开、受伤或切后台会中断，重新开始需完整计时    |
| 满包与物品   | 六格满包不吞掉搜索点；丢弃后可以拾回；带入物及丢弃重拾不能重复刷价值                 |
| 撤离         | 不足 100 价值不能撤离；达标后回撤离区，等待完整 5 秒成功；受伤、离区或价值下降会取消 |
| 结算与下一局 | 成功物品入库；失败按规则损失；返回准备后可再开局，物品不会重复入库                   |
| 存档与中断   | 成功后刷新保留仓库；局中刷新按中断失败处理；两个同源标签页不能同时写存档             |
| 正式页面     | 发布版能正常加载地图和角色；不显示开发专用模拟伤害/死亡按钮；错误消息可读            |
| 现有夜间玩法 | 手电、照明物资、攻击、抱抱与章节状态按当前界面规则工作；失败时记录具体操作及状态     |

先在一台电脑完成“开局、收集达标、撤离、刷新、再开局”的完整路线，再邀请更多测试者。规则单元测试不能替代真实路线、键盘手感和页面联动验收。

## 手机端验收

手机使用与电脑相同的 HTTPS 发布链接。触屏设备的整个网页按横屏尺寸排版：游戏区占满内容宽度并排在上方，物资价值、夜间装备、任务、行前准备、背包、结算和仓库依次排在下方。准备页和对局中均可滚动整页查看；背包按钮滚动到下方背包区。规则和图鉴使用横屏弹窗。开始探索或点击“全屏”时尝试浏览器全屏及横屏锁定；不支持这些接口的浏览器使用页面旋转兼容，摇杆坐标同步转换。画布按容器未旋转前的尺寸重新渲染，不拉伸画面。真实旋转及浏览器地址栏伸缩时会重算布局并清除按住的操作。桌面窄窗口不会触发页面旋转或手机摇杆。

在至少一台 Android 手机和一台 iPhone 上检查（含关闭全屏权限的场景）：

手机首屏采用一行状态与操作栏，隐藏大标题，游戏区使用剩余高度；角色缩放按宽度计算，避免浏览器上下工具栏挤压画面后角色过小。“出发／背包／结算”按钮按当前阶段跳到下方面板。应额外检查内置浏览器工具栏未收起、可用横屏高度约 300px 的情况。

音乐与音效共用一个 Web Audio 通道，首次点击后解锁；顶部“开启声音”按钮可手动恢复，播放后可静音。验收时分别触发移动、低生命、攻击、拾取、受伤、开箱、撤离和怪物叫声，确认背景音乐持续且各音效可叠加；再检查切后台后点击恢复、静音与恢复音量，以及加载失败后的“重试声音”。这些项目仍需要实机验证。

| 场景           | 通过标准                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 首屏与方向     | 竖屏、横屏均可查看必要信息；地图、面板和控件不相互遮挡；刘海与底部安全区不挡操作                                  |
| 上下排版与滚动 | 准备、对局、结算均为游戏在上、其他面板在下；从地图空白处或面板滑动可到出发、背包和返回准备按钮；拖摇杆不会滚页    |
| 游戏画面与尺寸 | 地图上有角色、建筑和手电光，小地图有内容；首次加载、横竖屏切换及地址栏伸缩后均无空白或拉伸                        |
| 手机音乐       | iPhone Safari 与 Android 点击继续或开始后有循环音乐；首次播放被拒绝后再点击可恢复；放弃后操作面板不会自动重启音乐 |
| 触屏移动       | 显示左侧摇杆与右侧技能按钮；摇杆持续移动并决定朝向；松手停止；双指移动与交互可同时响应                            |
| 搜索与其他操作 | 可完成持续搜索、攻击和现有夜间操作；释放手指、取消触点或离区不会继续误触                                          |
| 背包与结算     | 无键盘也能选物品、丢弃、使用、撤离、放弃和返回准备；长名称与提示不溢出                                            |
| 中断与旋转     | 切后台、锁屏、旋转及页面失焦不会留下持续移动或持续交互；返回后状态符合对局规则                                    |
| 存档能力       | 支持 Web Locks 时开局、结算与刷新正常；不支持时有明确提示，不出现半开的对局或损坏存档                             |
| 实机体验       | 控件尺寸可可靠点击；拖动控件不会意外滚动或缩放；小屏下仍可分辨角色、目标和生命值                                  |

## 反馈格式

```text
测试版本/日期：
电脑或手机：
设备、系统、浏览器：
发生问题前的操作：
期望结果：
实际结果：
是否能重复发生：
截图/录屏：
```

只写“卡了”或“打不开”难以定位；加载失败时补充所在网络和页面提示，游戏异常时补充当前生命、价值、背包与对局阶段。

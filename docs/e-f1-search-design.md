# F1 搜索与地点调查

## 设计状态

已实现参考版本（当前仓库主流程）；正式库存、战斗和剧情服务接入时沿用本接口契约。

## 目的与入口

玩家在校园搜索点附近按住 E 调查地点。搜索成功后生成一个来源为 `raid-loot` 的物品实例，交给库存服务校验容量和来源，再更新本局临时任务证据。界面只显示状态，不直接修改库存或永久存档。

## 前置条件与规则

- 对局阶段为 `active`，玩家存活且未暂停。
- 玩家在搜索点范围内，视线无遮挡，夜间区域有足够照明。
- 湖畔异常羽毛需要本局仍携带残缺手记；不满足时不会消耗搜索进度。
- 必须持续按住 E 且未移动，搜索时长由 `RAID_RULES.searchDurationMs`（当前 2 秒）提供。
- 松键、移动、受伤、页面切后台或阶段变化都会调用 `cancel()`。
- 背包满或库存拒绝时不标记地点已打开，搜索点保留，可腾挪后重试。
- 物品实例使用 `${raidId}:${pointId}`，来源和对局 ID 用于有效价值计算，不能通过重复搜索刷分。

## 调用顺序

1. 键盘或触屏输入由 `TouchControls.held("E")` 与 Phaser 键盘状态统一提供给 `WorldScene`。
2. `WorldScene.interact` 读取对局阶段、范围、视线、夜间光照和调查前置；附近掉落物拾取、抱抱请求和充电交互优先于搜索点。
3. `SearchInteraction.begin(pointId)` 建立一次搜索计时。
4. 每帧读取 `progress()`；完成后构造 `ItemInstance`。
5. `SearchInteraction.finish(item, inventory.addLoot)` 先执行库存写入，成功才标记地点打开。
6. 成功后发出 `LocationInteracted`，由任务模块更新本局临时证据；永久章节必须由成功结算流程提交。

`SearchInteraction` 也被灯站充电复用，但充电使用 `charge:${lamp.x}` 的临时目标，不会创建物品或发出地点调查事件。

## 异常与恢复

| 场景                     | 结果                                   | 恢复                       |
| ------------------------ | -------------------------------------- | -------------------------- |
| 松键、移动、受伤、切后台 | 进度归零，物品不生成                   | 返回范围并重新长按         |
| 缺少手记调查羽毛点       | 不开始计时                             | 先完成前置调查并仍携带证据 |
| 背包满                   | 进度结束但库存拒绝，搜索点不打开       | 丢弃/消耗后重试            |
| 重复搜索已打开点         | `begin` 返回 false                     | 不能重复领取               |
| 对局结束或刷新           | 场景清理交互；活动局由存档恢复规则处理 | 新局重新开始               |

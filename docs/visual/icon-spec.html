一、两类图标 不是缩放关系，是两套

常见错误是「先画一个 64 的，再缩到 20 用」。缩放会让描边一起变小：64 网格上的 3px 描边缩到 20px 只剩 0.94px，在暗底上直接糊掉。正确做法是每个渲染尺寸单独算描边，所以按尺寸分成两类。

UI / 功能性

24 网格 · 2px 描边 · 渲染 16–32px。跟着按钮和标签走，单色 currentColor。

  • 可视区域 2–22，四周留 2px 安全边
  • 只有描边，没有填充
  • 圆头圆角（round / round）
  • 本页 14 个全部属于这一类

图鉴 / 说明性

64 网格 · 3px 描边 · 渲染 56–96px。保持现状不改，避免无意义返工。

  • 已存在于 ui/codex.ts 的 iconPaths
  • 11 个：医疗箱、纸张、橡皮、地图、座位、咖啡、徽章、羽毛、钥匙、蝙蝠、锁
  • 未来新增图鉴物品图沿用这套，不要混进 24 网格

二、24 网格怎么画 五条几何硬规则

  1. 画布 24×24，可视区 2–22。四周 2px 安全边，避免图标和容器描边相切（UI 里按钮描边就是 1px，贴边会粘在一起）。
  2. 描边 2px，不缩放。24 格配 2px 的视觉重量，约等于 64 格配 5.3px；跟现有 64/3 相比更「厚」，这是小尺寸必须的补偿。
  3. 圆头圆角。stroke-linecap: round + stroke-linejoin: round。方头在 16px 下会出现毛刺。
  4. 只用 currentColor。图标跟随文字色，状态色（危险/成功）由父级 color 决定，不用给图标单独配色。
  5. 单条 path，多段用空格分隔。不写 fill，不写 style，便于统一替换与批量校验。

三、14 个图标 16 / 20 / 24 / 32 四档实渲染

下面每一格都是真实渲染，不是图片。字号档位对应关系：16 用于行内小图标，20 用于按钮内图标， 24 用于导航栏，32 用于空状态插图。中间值（18、22）不要用——多一档就多一套需要人眼复核的东西。

Motion Spec · V1.1

动效规范

V1.0 冻结时全项目 0 条 transition、0 个 @keyframes、0 个 Phaser tween，界面状态全是瞬变。 所以这一节不是收敛旧值，是从零定义：四档时长、三档缓动、五条硬规则。 下面每一行都可以点，点了才会动 —— 静态截图看不出动效，只能现场跑。

--dur-base 实测 读取中… --ease-out 实测 读取中… 动效偏好检测中…

一、时长四档 1.5 倍阶梯，上限 320ms

点任意一行播放。四档之间必须能一眼分出快慢，否则档位没有意义； 但如果慢到让人等，就说明用错了档 —— 界面反馈永远不该成为等待。

二、缓动三档 同样 200ms、同样距离，只换曲线

三张卡片的时长和位移完全一致，差别只在曲线。点一下能看出：进入型「快出慢停」像落到位， 退出型「慢起快走」像被抽走，位移型两端都缓、看着最稳。选型按「动的东西往哪去」，不按手感。

三、五条硬规则

  1. 只动 opacity 与 transform。不动 width / height / top / left —— 那些触发重排，低端安卓直接掉帧。
  2. 不做回弹。没有 overshoot、没有弹簧、没有弹跳。这套视觉是硬边档案感，一回弹立刻变廉价。
  3. 上限 320ms。超过就不是界面反馈，是动画片。开局剧情那种「要看」的内容另算，但不走这套令牌。
  4. 进入用 ease-out，退出用 ease-in，位移用 ease-in-out。不按手感随手挑。
  5. 系统减少动效时全部归零。--dur-* 在 prefers-reduced-motion: reduce 下被重定义为 0ms，写了 var(--dur-*) 的组件自动退回瞬变，不需要逐个组件写媒体查询。

四、哪个交互用哪一档 冻结后按此表取值，不自创时长

交互 时长 缓动 动什么
按钮按下 / 松开 --dur-instant --ease-out 底色明度、1px 内位移
勾选框打勾 --dur-instant --ease-out 描边转填充
悬停、焦点环 --dur-fast --ease-out 描边色、外发光透明度

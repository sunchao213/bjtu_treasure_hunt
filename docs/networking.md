# 联机房间（第一轮）

## 能力范围

服务端创建不重复的随机 6 位数字临时房间，房主可将人数上限设为 2～10 人，也可关闭凭房间号加入。人数上限不能低于当前成员数。修改规则会清除所有成员的准备状态，队友确认后重新准备；局中锁定规则。创建者自动成为房主，其他成员全部准备后，只有房主能开始游戏。等待期间可主动将房主转交给在线队友，转交后重新准备；房主退出后自动转交给最早加入的剩余成员；所有人退出时房间解散。游戏进行中不接收新成员，所有成员结束本局后回到原房间准备下一局。

房间成员、地图标记和账号信息统一使用注册昵称，服务端以登录账号为准，不接受客户端伪造昵称。开局时所有成员出现在同一张校园地图的南门附近，最多 10 个出生位置互不重叠。客户端每 50ms 发送本轮 ID 和方向输入；服务端统一计算坐标并广播，自己的角色和其他成员使用同一份坐标。重复、过期轮次和结算后的输入不会推进位置。

客户端和服务端共用 `src/config/campus-geometry.json`，包含地图尺寸、南门位置、260 的移动速度、玩家半径、建筑与湖面碰撞范围；服务端将该文件嵌入程序集。每局按服务端本轮 ID 生成相同宝箱布局，下一局重新生成。队友与自己使用相同的角色贴图、尺寸和四方向待机／行走动画，以头顶注册昵称区分；小地图及展开校园图使用蓝点显示所有在线队友。局内队伍栏显示昵称及探索／已结束状态。大厅和局内每 3 秒测量连接往返延迟，未收到心跳回复超过 10 秒后自动重连，并忽略旧连接的回调。断线会移除成员，等待中的开放房间可自动重连加入，准备状态需要重新确认。关闭加入或局中断线不保证恢复成员资格。

房间已共享地图布局和玩家坐标；敌人、战斗命中、拾取后的宝箱状态、掉落、任务进度和撤离结算仍由各客户端运行。账号进度通过 HTTP 保存到 SQLite 云存档，由浏览器单写者锁和服务端租约保护。同账号不能在两个设备同时游戏，两人联机请使用不同账号。在线房间是第一轮的同图玩家联机基础，不代表合作战斗已完成。

## 本地启动

终端一启动服务端：

```powershell
dotnet run --project server/OnlineHost.csproj --urls http://127.0.0.1:5080
```

终端二启动前端：

```powershell
npm.cmd run dev
```

先在首页注册或登录，点击顶部“联机房间”（手机工具栏“房间”），自动连接服务。房主点击“创建房间”并分享生成的房间号，队友输入 6 位房间号加入。在房间内选择装备并确认风险，队友点击“准备”，房主在所有队友准备后点击“开始游戏”，所有成员同步开启各自的探索。准备后可取消准备修改装备。健康检查地址为 `http://127.0.0.1:5080/health`。`/api` 与 `/ws` 统一通过前端同源代理，自动携带账号会话，无需配置 `VITE_GAME_WS_URL`。局域网或正式环境应通过 HTTPS/WSS 提供同源代理。

## 协议和安全边界

协议版本为 1，消息定义在 `src/modules/network/network-protocol.ts`。客户端发送身份展示信息、房间操作、方向输入、朝向和交互按钮状态；服务端只接受有限长度消息，校验版本、输入序号和字段，限制房间人数及输入频率，并返回服务端生成的玩家 ID 和位置快照。

房间操作包括 `create-room`、`join-room`、`set-ready`、`room-settings`、`transfer-host`、`start-game`、`finish-game` 和 `leave-room`。`room-state` 包含房主 ID、当前人数上限、加入权限 `admissionOpen`、准备/结算状态和本轮 ID。客户端以服务端本轮 ID 去重启动，并忽略旧快照。容量检查、规则变更、房主权限和全员准备校验在同一把锁内完成，避免并发加入超员或未准备时抢先开局。自动验收运行 `npm run test:server`，覆盖人数和加入权限、规则变更清除准备、主动转交、12 个连接并发加入、满员拒绝、准备/取消和多轮开始。

服务端要求有效账号会话后才接受 WebSocket，联机昵称来自登录账号。退出或会话到期会中断连接，重新登录后可再次连接房间。账号密码哈希持久化、Cookie、登录限流和部署要求见[登录功能说明](authentication.md)。静态 GitHub Pages 无法单独承载账号与 WebSocket 服务，需要同源后端或代理。

## 手工验收

1. 两个浏览器分别登录账号，创建房间并输入生成的房间号加入，房间人数显示 2/10，昵称与注册昵称一致。队友准备前房主不可开始，准备后房主开始，双方同时进入探索并能看到彼此移动。不同账号的存档分别保存。
2. 改用不同房间号，玩家互不可见；离开房间后对方收到移除状态。
3. 关闭服务端后客户端显示连接异常；重启会使登录会话失效，需要重新登录、连接房间。已确认云进度保留，中断探索按失败处理。
4. 发送错误协议或格式错误的 JSON，服务端拒绝消息；位置由服务端根据输入计算并限制在地图边界内。
5. 在线期间分别完成开局、结算和云存档检查，确认房间消息不修改账号库存或结算；退出游戏后换设备登录同一账号，检查仓库一致。
6. 未登录时访问 `/api/auth/me` 或尝试 WebSocket 握手均返回 401；退出后旧连接断开、旧 Cookie 不能再进入房间。
7. 10 个账号加入同房间后开始，实际游戏客户端应各看到另外 9 个角色。双方移动后，对方显示的位置与自己的逻辑坐标一致；建筑和湖面都不能穿越。双方宝箱布局一致，下一局全员回到南门出生区域，小地图上的蓝点随队友移动。

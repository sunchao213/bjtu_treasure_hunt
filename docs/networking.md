# 联机房间（第一轮）

## 能力范围

服务端提供 8 人以内的临时房间、在线玩家位置快照、昵称和朝向。客户端每 50ms 发送方向输入；服务端按固定最大速度、时间步长和地图边界推进位置，丢弃乱序输入，并将房间快照广播给成员。玩家断线后从房间移除，客户端会自动尝试重连并重新加入原房间。

当前没有跨客户端共享敌人、战斗命中、掉落、任务进度或撤离结算。每个客户端仍运行自己的单人对局；账号进度通过 HTTP 保存到 SQLite 云存档，由浏览器单写者锁和服务端租约保护。同账号不能在两个设备同时游戏，两人联机请使用不同账号。在线房间是第一轮的同图玩家联机基础，不代表合作战斗已完成。

## 本地启动

终端一启动服务端：

```powershell
dotnet run --project server/OnlineHost.csproj --urls http://127.0.0.1:5080
```

终端二启动前端：

```powershell
npm.cmd run dev
```

先在首页注册或登录，再在页面右侧“设置 / 联机房间”中连接并加入相同房间号；两个浏览器窗口会看到彼此的玩家标记。健康检查地址为 `http://127.0.0.1:5080/health`。`/api` 与 `/ws` 统一通过前端同源代理，自动携带账号会话，无需配置 `VITE_GAME_WS_URL`。局域网或正式环境应通过 HTTPS/WSS 提供同源代理。

## 协议和安全边界

协议版本为 1，消息定义在 `src/modules/network/network-protocol.ts`。客户端发送身份展示信息、房间操作、方向输入、朝向和交互按钮状态；服务端只接受有限长度消息，校验版本、输入序号和字段，限制房间人数及输入频率，并返回服务端生成的玩家 ID 和位置快照。

服务端要求有效账号会话后才接受 WebSocket，联机昵称来自登录账号。退出或会话到期会中断连接，重新登录后可再次连接房间。账号密码哈希持久化、Cookie、登录限流和部署要求见[登录功能说明](authentication.md)。静态 GitHub Pages 无法单独承载账号与 WebSocket 服务，需要同源后端或代理。

## 手工验收

1. 两个浏览器分别登录账号，再用相同房间号连接，房间人数显示 2，双方能看到彼此移动。不同账号的存档分别保存。
2. 改用不同房间号，玩家互不可见；离开房间后对方收到移除状态。
3. 关闭服务端后客户端显示连接异常；重启会使登录会话失效，需要重新登录、连接房间。已确认云进度保留，中断探索按失败处理。
4. 发送错误协议或格式错误的 JSON，服务端拒绝消息；位置由服务端根据输入计算并限制在地图边界内。
5. 在线期间分别完成开局、结算和云存档检查，确认房间消息不修改账号库存或结算；退出游戏后换设备登录同一账号，检查仓库一致。
6. 未登录时访问 `/api/auth/me` 或尝试 WebSocket 握手均返回 401；退出后旧连接断开、旧 Cookie 不能再进入房间。

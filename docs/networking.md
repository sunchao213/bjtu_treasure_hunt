# 联机房间（第一轮）

## 能力范围

服务端提供 8 人以内的临时房间、在线玩家位置快照、昵称和朝向。客户端每 50ms 发送方向输入；服务端按固定最大速度、时间步长和地图边界推进位置，丢弃乱序输入，并将房间快照广播给成员。玩家断线后从房间移除，客户端会自动尝试重连并重新加入原房间。

当前没有跨客户端共享敌人、战斗命中、掉落、任务进度或撤离结算。每个客户端仍运行自己的单人对局；本地存档继续由浏览器单写者锁保护。在线房间是第一轮的同图玩家联机基础，不代表合作战斗已完成。

## 本地启动

终端一启动服务端：

```powershell
dotnet run --project server/OnlineHost.csproj --urls http://127.0.0.1:5080
```

终端二启动前端：

```powershell
$env:VITE_GAME_WS_URL = "ws://127.0.0.1:5080/ws"
npm.cmd run dev
```

页面右侧“设置 / 联机房间”中连接后加入相同房间号；两个浏览器窗口会看到彼此的玩家标记。健康检查地址为 `http://127.0.0.1:5080/health`。局域网测试时让服务监听局域网网卡，并将前端地址改为 `ws://<服务端局域网IP>:5080/ws`。

## 协议和安全边界

协议版本为 1，消息定义在 `src/modules/network/network-protocol.ts`。客户端发送身份展示信息、房间操作、方向输入、朝向和交互按钮状态；服务端只接受有限长度消息，校验版本、输入序号和字段，限制房间人数及输入频率，并返回服务端生成的玩家 ID 和位置快照。

当前服务端不含账号认证，昵称不是身份凭据；适用于本地或可信课程局域网试用。公开部署前必须配置 HTTPS/WSS、身份认证、持久化策略、速率/连接限制、日志和隐私告知。不要把它直接暴露到公网。静态 GitHub Pages 不能承载 WebSocket 服务，前端和服务端需要分别部署。

## 手工验收

1. 两个浏览器用相同房间号连接，房间人数显示 2，双方能看到彼此移动。
2. 改用不同房间号，玩家互不可见；离开房间后对方收到移除状态。
3. 关闭服务端后客户端显示重连状态；恢复服务后自动重新加入之前房间。
4. 发送错误协议或格式错误的 JSON，服务端拒绝消息；位置由服务端根据输入计算并限制在地图边界内。
5. 在线期间分别完成本地开局、结算和存档检查，确认房间消息不修改本地库存或结算。

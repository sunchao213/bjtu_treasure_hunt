# 排行榜（R16）

## 口径

- 好友榜和全服榜共用同一指标：服务器记录时间落在最近 7 天窗口内的**成功撤离带出价值总和**。
- 窗口使用服务器 UTC epoch 毫秒，范围为 `[windowEndMs - 7 天, windowEndMs)`；`windowEndMs` 是生成快照时的服务器当前时间。接口同时返回窗口边界和快照更新时间。
- 仅成功局累计分数；失败局仍留档，但不计入总分。价值沿用结算中的 `RaidResult.value`，即当前局搜集价值，不把带入物价值算入其中。
- 近 7 天至少有一局成功撤离的玩家才进入榜单。新账号、零成功局或只有失败局的玩家不显示、不占名次。
- 排序依次为：总价值降序、单局最高价值降序、账号内部 ID 升序。玩家内部 ID 只用于确定稳定顺序，不返回客户端。总价值和最高单局价值相同者显示并列名次，后续名次按竞赛排名留空（如 1、1、3）。
- 榜单快照将窗口、昵称、聚合结果和排序位置固化 24 小时；游标按快照内排序位置继续。过期游标返回 410，客户端应重新获取第一页。
- 好友快照只包含创建时已接受的好友关系；每次翻页都会重新检查关系和双方屏蔽。如果解除好友或任一方屏蔽，后续页面立即隐藏对方；新建立的好友要刷新榜单才能加入当前快照。删除账号由外键级联删除成绩与快照行。
- 昵称在单个快照中冻结，改名后刷新生成新快照即显示新昵称。账号 UID 不暴露在榜单响应中。

## 存储与接口

- `raid_results` 按 `(user_id, raid_id)` 唯一，云存档写入事务发现一个此前未结算的 `lastResult.raidId` 时追加记录；重复请求不会重复插入，数据库触发器拒绝更新。
- 同一事务同时提交云存档和成绩行，写入失败时不会产生单边成绩。服务端按首次接受该新结算的 UTC 时间写 `settled_at_ms`。
- `GET /api/leaderboard?scope=friends|global&cursor=...` 需要登录 Cookie。首请求创建 24 小时快照；后续请求用 owner/scope 绑定的随机不透明游标令牌读取下一页，每页 20 人。排序尾键保存在服务端，不会把内部 ID 编码到 URL。
- 返回字段：`scope`、`windowStartMs`、`windowEndMs`、`updatedAtMs`、`entries`、`nextCursor`、`hasMore`。条目展示 `rank`、昵称、总价值、最高单局价值和成功撤离次数。
- 数据库 `user_version=3`。旧库启动时通过幂等 schema 脚本创建新增表和索引；旧的 `lastResult` 不回填，因为旧数据没有可信服务器结算时间。

## 可信度边界

当前战斗、掉落和撤离结算仍由客户端模拟。排行榜仅确保账号归属、首次结算接收时间、每局唯一性、服务端排序/窗口和存储不可变；它**不能证明客户端上报的成功状态或价值没有被篡改**。因此现阶段应作为原型/测试榜，不应用于奖励或正式竞技。要开放正式竞争，必须先把对局状态、掉落和撤离验证移到权威服务器，再由服务器产生 `raid_results`。

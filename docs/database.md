# SQLite 数据库

默认数据库为 `server/data/game.db`。ASP.NET 服务首次启动自动建库、初始化表并迁移同目录旧账号，无需安装单独的 SQLite 服务。驱动由 `dotnet restore server/OnlineHost.csproj` 下载。Node 工具需要项目约定的 Node 24。

## 初始化与位置

```powershell
# 可选：只创建数据库和表，不启动服务，不覆盖已有数据
npm.cmd run db:init

# 正常启动也会自动建库
dotnet run --project server/OnlineHost.csproj --urls http://127.0.0.1:5080
```

可用环境变量指定持久目录，启动服务、初始化和备份时使用相同配置：

```powershell
$env:Auth__DataDirectory = 'E:\BJTU-data'
```

一个数据库只供一个 ASP.NET 宿主进程使用，启动时会撤销旧租约；不要让多个宿主同时指向它。数据库、WAL 文件和备份已被 Git 忽略，不推送玩家数据。

## 表与一致性

| 表               | 保存内容                                       | 约束                                |
| ---------------- | ---------------------------------------------- | ----------------------------------- |
| `accounts`       | 账号 ID、用户名、昵称、密码盐和哈希、创建时间  | ID 主键；用户名忽略大小写唯一       |
| `player_saves`   | 每账号完整 JSON 快照、版本、更新时间、写入租约 | 账号外键及主键；JSON 有效；版本非负 |
| `legacy_imports` | 旧文件迁移来源和时间                           | 每来源只迁移一次                    |

表定义在 `server/Database/schema.sql`，当前 `user_version=1`。快照使用游戏存档 schema 3，包含仓库、图鉴、章节、进行中的探索、已结算局 ID 和最近结算。数据库启用 WAL 和外键，以事务、参数化 SQL、账号会话、版本比较和租约保护写入；同一保存请求丢失响应后重试不会重复递增版本。

`accounts.json` 首次迁移保留原账号 ID、盐与密码哈希，原文件不删除。同目录有无效记录或冲突时整批迁移回滚，服务停止启动，需检查原数据后重试。不要删除迁移标记来强制重导入。

浏览器账号旧存档仅在云端无存档时自动上传；云端已有数据时优先远端。添加登录前的共享存档在游戏内手动确认迁移。HTTP 写入仅从当前会话确定账号，不接受客户端指定其他账号。服务校验快照结构、来源和基本一致性，但当前不负责权威战斗与掉落计算。

## 备份与恢复

```powershell
npm.cmd run db:backup
```

备份保存在 `server/backups/game-时间.db`，使用 SQLite backup API 获取一致快照，服务运行时也可执行。不要在服务运行期间仅复制 `game.db`，已提交数据可能仍在 `game.db-wal` 中。备份包含账号哈希与玩家数据，应限制访问并定期复制到持久备份位置。

恢复步骤：

1. 停止游戏服务，确认没有其他进程使用目标数据库。
2. 将现有 `game.db` 及存在的 `game.db-wal`、`game.db-shm` 一起保留到独立目录，便于回退。
3. 将选定的一致性备份复制到目标数据目录并命名为 `game.db`；目标目录不能残留旧数据库的 WAL/SHM 文件。
4. 使用该目录重新启动服务，重新登录并检查账号和仓库。会话不在备份中，恢复后需重新登录。

游戏内导出 JSON 只备份当前账号游戏进度，不包含账号和密码哈希，也不能替代整个数据库备份。

## 验证

`npm.cmd run test:database` 验证实际 SQL 的唯一键、外键、JSON、版本约束、回滚、重复初始化和 WAL 备份。`npm.cmd run test:server` 验证真实 .NET 驱动、旧账号迁移、Cookie、账号隔离、租约、云存档和重启持久化。

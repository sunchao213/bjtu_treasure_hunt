## 1 为什么分成两类，不是缩放关系

图鉴的 64 网格配 3px 描边，缩到 20px 渲染时描边只剩 `3 × 20/64 = 0.94px`。在 `#111313` 的暗底上，1px 以下的描边会被抗锯齿吃掉一半亮度，结果是发灰、边缘糊。

这不是审美问题，是光学问题：**描边宽度必须跟着渲染尺寸重算，不能跟着画布一起缩。**

| 类别          | 网格 | 描边 | 渲染尺寸          | 用途                     |
| ------------- | ---- | ---- | ----------------- | ------------------------ |
| UI / 功能性   | 24   | 2px  | 16 / 20 / 24 / 32 | 按钮、导航、标签、引导卡 |
| 图鉴 / 说明性 | 64   | 3px  | 56–96             | 物品图鉴大图、空状态插图 |

换算参考：24 格配 2px ≈ 64 格配 5.3px。也就是说 UI 这套的笔触相对更粗，这是小尺寸必须的补偿，不是画风不一致。

## 2 五条几何硬规则

1. **画布 24×24，可视区 2–22。** 四周留 2px 安全边，避免图标与 1px 容器描边相切粘在一起。
2. **描边 2px，不缩放。** 写在 `stroke-width`，不用 `transform: scale()` 调大小。
3. **圆头圆角。** `stroke-linecap: round` + `stroke-linejoin: round`。方头在 16px 下出毛刺。
4. **只用 `currentColor`。** 图标跟随父级 `color`，状态色由容器 class 决定，不给图标单独配色。
5. **单条 path、多段空格分隔、不写 fill。** 便于统一替换、批量校验、整体换色。

## 4 对与错

| 判断 | 做法                                  | 原因                                               |
| ---- | ------------------------------------- | -------------------------------------------------- |
| ✓    | 尺寸只用 16 / 20 / 24 / 32            | 中间值（18、22）每多一档就多一轮人眼复核，收益为零 |
| ✕    | 用 `transform: scale()` 把 24 缩到 18 | 描边会一起缩到 1.8px，边角开始糊                   |
| ✓    | 颜色交给父级 `color`                  | 同一图标在成功/危险态复用，模板换个 class 就行     |
| ✕    | 给图标写死红色                        | 「关闭」是中性动作，红色会被误读成危险操作         |
| ✓    | 纯文字按钮不必硬加图标                | 「开始探索」文案已清楚，加图标只是噪声             |
| ✕    | 拿字符当图标（现在的 `×`）            | 基线、粗细、光学大小都不可控，还会随字体回退变形   |

空白律参考：图标与文字并排时，间距取 `--space-2`（8px）；按钮内图标取 20px，与 13px 文字视觉重量相当。
